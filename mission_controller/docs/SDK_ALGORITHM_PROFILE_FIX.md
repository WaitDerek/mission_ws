# SDK 离线算法配置修复（2026-09-27）

## 修复范围

- `Algo(model, force, dh=...)` 在 SDK v1.1.5 中会切换为通用模型；改为先保留控制器的 RXL75/RXR75 型号，再调用 `rm_algo_set_dh()`。
- 同步控制器实际 DH（8 行）、安装角、关节限位、Tool/Work Pose。读取失败或存在无效数值时中止，不回退到厂家默认模型。
- 算法配置按 SDK 连接缓存，每次算法任务都重新应用完整配置。控制器标定/Tool/Work 修改后应重新连接或重启 Mission。
- 离线 IK、连续 IK、关节路径检查和力控启动的连接句柄 FK 共用进程级算法锁。连接句柄 FK/IK 会加载控制器配置，不能把它误认为恢复出厂 DH。
- 不修改控制器 DH，不改变已有的 MoveJ 顺序、力控参数、配置限位或任何层的检测/避让角度。Layer4 本次不处理。

## 验证

- 新增控制器配置完整性、失败拒绝、实际型号保留、非零 Tool/Work、力控 FK 与离线计算串行化测试。
- 只读连接两臂：各 3 组姿态，与连接句柄 FK 对照前故意插入另一臂 FK；离线 FK 位置/姿态差为 0，6 次 IK 回算位置误差均小于 0.001 mm。
- 当前两侧控制器安装角均为 `[0,-90,0]` 度。该值从控制器读取，不硬编码。
- 右臂当时实际姿态的 SDK 自碰撞/限位结果为 1，连接句柄和修正离线模型一致；这不等于确认实物已碰撞，也不能称该姿态通过安全检查。SDK 检查不覆盖整机、另一机械臂、料箱与外部障碍。

## 测试隔离与部署

首次全套测试未隔离 ROS 域，误将测试目标交给真实 `/execute_workflow`，触发了导航和观测；两个目标最终状态分别为 CANCELED、ABORTED，没有继续抓取。这是测试环境错误。

`test/conftest.py` 现在强制测试使用 ROS 域 197 和 localhost，并移除继承的 CycloneDDS 网卡配置。不要在域 197 上部署真实机器人。测试不得连接真实 SDK 或自行发送 MQTT。

独立域全套测试通过。构建使用常规 merge-install（不要使用 symlink-install），避免 April Python 无法发现包 metadata。构建后手动重启 Mission 才会加载修复；不自动启动运动。
